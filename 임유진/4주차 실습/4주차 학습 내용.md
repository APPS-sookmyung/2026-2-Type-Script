# TypeScript Interface

## 옵션, 인덱스 시그니처, 맵핑된 타입

- 인터페이스: 객체 정의 시 속성이 누락되거나 정의되지 않는 속성을 갖고 있다면 컴파일이 되지 않음

### 인터페이스의 추가적인 기능

**1. 선택적 속성**

- 넣어도 되고 안 넣어도 되는 속성
- 조건문 대신 사용할 수 있는 연산자: `??`

```ts
function printDescription2(product: Product): void {
  console.log((product.description ?? "No desc").toUpperCase());
}
```

**2. 읽기 전용 속성**

- 한 번 주어진 값을 읽을 수만 있고 수정은 할 수 없음
- `readonly` 사용
- 보안상 중요한 값 등 초기 설정 후 불변이어야 하는 값을 지정할 때 유용하게 사용
- 읽기 전용 속성이 참조 값일 경우: 속성에 새로운 배열을 할당하면 컴파일 오류 발생

**3. 함수 타입에서의 사용**

```ts
interface MathOperation {
  (a: number, b: number): number;
}

const add: MathOperation = function (a, b) {
  return a + b;
};

const multiply: MathOperation = (a, b) => a * b;

console.log(
  add(1, 2).toFixed(2), // 3
  multiply(3, 4), // 12
);
```

### 인덱스 시그니처

- 속성을 지정하지 않고, 속성과 값으로 사용할 수 있는 타입만 지정하는 방법

```ts
interface PhoneBook {
  [name: string]: string;
}
```

- `[name: string]`: 속성의 키로 문자열 타입의 어떤 값이든 사용할 수 있음을 의미
- 이때 `name`은 단순한 식별자이기에 다른 이름으로 바뀌어도 상관 없음

### 매핑된 타입

- 인터페이스의 대안으로 사용될 수 있음
- 특정 키 집합을 기반으로 동일한 구조의 타입을 자동 생성할 때 매핑된 타입을 사용할 수 있음

## 인터페이스2

### 상속

- 다중상속을 통해 둘 이상의 인터페이스를 조합할 수 있음
- 타입이 다른 두 속성을 상속하면 충돌 발생
  - 해결 방법
  1. 두 인터페이스의 속성명을 다르게 하기
  2. 속성의 이름이 같아야 하는 경우 타입 유니언 사용 가능

```ts
interface CanRun {
  run(): void;
}

interface CanBark {
  bark(): void;
}

interface Dog extends CanRun, CanBark {}
```

### 중첩된 인터페이스

```ts
interface ContactInfo {
  phone: string;
  email: string;
}

interface Employee {
  name: string;
  contact: ContactInfo;
}
const dev: Employee = {
  name: "Jane",
  contact: {
    phone: "010-1234-5678",
    email: "jane@example.com",
  },
};
```

### 병합

- 무분별하게 사용하면 구조를 파악하기 어려울 수 있으므로 명확한 목적이 있을 때만 사용하는 게 좋음

### 클래스 적용

- `implements`라는 키워드를 사용해 클래스에 인터페이스 적용 가능

### 다중 구현

```ts
interface Flyer {
  fly(): void;
}

interface Swimmer {
  swim(): void;
}

class Duck implements Flyer, Swimmer {
  fly(): void {
    console.log("Duck is flying");
  }

  swim(): void {
    console.log("Duck is swimming");
  }
}
```

### 타입 별칭

- `interface` 대신 `type` 키워드 사용
- 타입과 다르게 값을 할당하거나, 속성을 누락하거나, 초과 속성을 넣으면 오류 발생

### 읽기 전용 (맵드 타입)

```ts
interface Product {
  name: string;
  price: number;
}

type ReadonlyProduct = {
  readonly [K in keyof Product]: Product[K];
};

const item: ReadonlyProduct = {
  name: "Pen",
  price: 1.5,
};

item.price = 2; // ❌
```

## 객체 지향 프로그래밍

- 데이터와 그 데이터를 다루는 함수들을 하나의 객체(object)라는 독립적인 단위로 묶어 설계하고 개발하는 프로그래밍

**1. 캡슐화 (Encapsulation)**

- 속성과 메서드를 하나의 객체 안으로 묶고 은닉하는 것
- 간섭을 줄이고 안정성을 높임

**2. 상속 (Inheritance)**

- 이미 만들어진 부모 클래스의 속성과 기능을 자식 클래스가 물려받아 사용할 수 있는 기능
- 적은 중복과 편리한 유지보수

**3. 다형성 (Polymorphism)**

- 같은 이름의 기능이나 메서드가 객체의 종류에 따라 다르게 동작하도록 하는 것
- 코드를 유연하게 만들고 확장성을 높임

**4. 추상화 (Abstraction)**

- 핵심적인 특징만 추출하고 불필요한 세부 사항은 숨기는 것
- 프로그램의 복잡도를 낮추고 설계에 집중 가능

# TypeScript 네임스페이스와 모듈

## 네임스페이스와 모듈

### 네임스페이스

- 내부 모듈이라고도 불렸으며, ES6 이전 JavaScript에서 주로 사용되던 방식
- 주로 전역 공간 오염을 방지하고 한 파일 내에서 여러 관련된 기능을 하나의 이름 아래 묶는 데 사용
- 이름들의 공간을 분리하고, 외부에서 사용할 수 있는 요소들을 특정할 수 있음
- 실무에서는 아주 소규모의 프로젝트가 아니면 잘 사용되지 않음

```ts
// Global scope pollution
const appName = "MyApp";

// Duplicate function declarations
function greet(name: string): string {
  return `Hello, ${name}! Welcome to ${appName}`;
}

function greet(name: string): string {
  return `Hi, ${name}!`;
}
```

위의 경우 JS에서는 함수가 덮어쓰여지지만, TS에서는 컴파일 오류 발생

```ts
namespace MyNamespace1 {
  export const appName = "MyApp";

  export function greet(name: string): string {
    return `Hello, ${name}! Welcome to ${appName}`;
  }
}

namespace MyNamespace2 {
  export function greet(name: string): string {
    return `Hi, ${name}!`;
  }
}

console.log(
  MyNamespace1.appName,
  // 서로 다른 네임스페이스에 속한 greet 함수
  MyNamespace1.greet("Alice"),
  MyNamespace2.greet("Bob"),
);
```

- `export`를 사용해 네임스페이스 밖으로 꺼내 쓸 수 있음

#### 네임스페이스의 중첩

```ts
namespace Company {
  export namespace HR {
    export class Employee {
      constructor(public name: string) {}

      getDetails() {
        return `Employee: ${this.name}`;
      }
    }
  }
}

const emp = new Company.HR.Employee("Bob");
console.log(emp.getDetails()); // Employee: Bob
```

## 모듈

- 실무에서는 파일 단위로 독립된 스코프를 가질 수 있게 해주는 모듈이 주로 사용됨

```ts
// Named export
export interface User {
  id: number;
  name: string;
  role: "admin" | "user";
}

export function isAdmin(user: User): boolean {
  return user.role === "admin";
}
```
